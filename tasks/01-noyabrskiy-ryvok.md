## Часть 2. Свой шаблон ввода-вывода

Создай `algo/_template.cs` — заготовку, с которой начинаешь каждую задачу. Каждое решение — отдельный файл, запуск:

```bash
dotnet run algo/cf/4A.cs < 4A.in
```

### Требования

- Читает целые числа из любого расположения во входе: в одной строке, по одному в строке, вперемешку.
- Умеет прочитать строку целиком (для задач на строки).
- Пишет много строк вывода быстро: копит вывод и сбрасывает один раз в конце.
- Не падает на пустых строках и лишних пробелах.

### Проверка

Сгенерируй большой тест:

```bash
python3 -c "print(200000); print(' '.join(['1000000000'] * 200000))" > big.in
```

Программа на шаблоне читает `n`, затем `n` чисел и печатает их сумму. Должно получиться `200000000000000`, и время работы самой программы — меньше 0,5 секунды (замерь `time`). Если сумма получилась странная — разберись почему, это и есть урок.

### Что гуглить, если застрял

`Console.OpenStandardInput`, `StreamReader`, `StringBuilder`, `Console.Out.Flush`, переполнение `int`.

Код шаблона пишешь сам. Готовый шаблон из интернета не копируем: на экзамене ты должен понимать каждую строку.

## Правила решения задач

1. **Сначала думаешь сам.** Не придумал за 30 минут — читаешь разбор (Tutorial на странице раунда), закрываешь его и пишешь решение сам. Через день решаешь эту задачу заново с нуля.
2. **Без нейросетей и чужого кода.** На экзамене их не будет, а тренируешь ты именно поиск решения.
3. **Каждая принятая задача (Accepted) — коммит:** `algo: cf 4A watermelon`.
4. **В конце файла — комментарий на 1–2 строки:** идея решения и сложность, например `// O(n log n): сортируем и идём двумя указателями`.
5. **Журнал `algo/LOG.md`:** задача, сколько минут ушло, сколько попыток, на чём ошибся. По журналу будем разбирать слабые места.
